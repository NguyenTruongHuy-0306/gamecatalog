## Commits

### `341ad7a` — Fix reset-password blocked for logged-in users; add plain URL fallback to emails

Two fixes in one commit:

**Middleware bug (`proxy.ts`)**
- `/reset-password` was listed in `AUTH_ONLY_ROUTES` alongside `/login` and `/signup`
- Logged-in users clicking a reset link from email were silently redirected to `/` before reaching the form
- Fixed by removing `/reset-password` from `AUTH_ONLY_ROUTES` — password reset must be accessible regardless of session state

**Email fallback (`email.ts`)**
- Added a plain-text URL below the button in the password reset and verify-email templates
- Wrapped in a `<p>` tag (not `<a>`) so it can't be stripped by email clients
- Also added a `text` plain-text body to both emails for email clients that don't render HTML

### `b91d3e2` — Show URL as plain text in emails so Gmail link-stripping doesn't block access

Discovered that Gmail strips all `<a>` tags from emails sent by unverified senders (`onboarding@resend.dev`). The button and the anchor-tag fallback added in the previous commit were both being removed.

- Replaced the `<a href>` fallback with a plain `<p>` containing the raw URL in a grey `#f4f4f4` box
- Plain text is never stripped — users can always select and copy it

### `5af515d` — Switch email sending from Resend to Gmail SMTP via Nodemailer

Attempted to bypass the Gmail link-stripping problem by sending emails directly from the user's Gmail account via SMTP:
- Installed `nodemailer` + `@types/nodemailer`
- Replaced Resend client with `nodemailer.createTransport` using `smtp.gmail.com:587`
- Added `GMAIL_USER` and `GMAIL_APP_PASSWORD` env vars to Vercel
- **Result: failed** — Vercel blocks all outbound SMTP connections to prevent spam abuse

## Session 6 — Automatic Game Release Status System

### Commit `7837ad2` — Add automatic game release status system (upcoming/released/classic)

Added a `ReleaseStatus` enum to the Prisma schema that auto-classifies every game based on its `releaseYear`:

| Status | Condition |
|--------|-----------|
| `upcoming` | `releaseYear > currentYear` |
| `released` | `currentYear - 9 ≤ releaseYear ≤ currentYear` |
| `classic` | `releaseYear ≤ currentYear - 10` |

**Schema / migration:**
- `ReleaseStatus` enum + `release_status` column added to `games` table
- Migration `20260611000000_add_release_status` populates existing rows from `releaseYear`
- Migration was applied manually via `prisma db execute` (previous deploy failures left a stale advisory lock)

**New files:**
- `src/lib/release-status-config.ts` — client-safe constants (`STATUS_LABELS`, `STATUS_COLORS`) and `computeReleaseStatus(year)` pure function; no Prisma import
- `src/lib/release-status.ts` — server-only; re-exports from config + `updateAllReleaseStatuses()` using Prisma batch update

**Files changed:**
- `prisma/schema.prisma` — `ReleaseStatus` enum + `releaseStatus` field on `Game`
- `src/app/api/games/route.ts` — `?status=` filter on GET; `computeReleaseStatus` on POST create
- `src/app/api/admin/sync/igdb/route.ts` — calls `updateAllReleaseStatuses()` after every IGDB sync
- `src/components/games/GameCard.tsx` — status badge next to year in card info row
- `src/app/(public)/games/[slug]/page.tsx` — status badge in game detail hero (next to quality tier badge)
- `src/components/games/GameFilters.tsx` — "Era" dropdown filter (All Eras / Upcoming / Released / Classic)
- `src/components/admin/AdminGamesTable.tsx` — "Era" column with colored badge
- `src/app/admin/games/page.tsx` — `releaseStatus: true` added to Prisma select
- `src/app/(public)/games/page.tsx` — `?status=` passed to API when filter is set

**Infra fixes required:**
- `DIRECT_DATABASE_URL` was empty in Vercel (previous `printf` pipe had no effect) — re-added via Bash
- Stale Prisma advisory lock on the database (from earlier failed deploy) — released via `prisma db execute SELECT pg_advisory_unlock_all()`
- Deploy succeeded on the third attempt ✅
