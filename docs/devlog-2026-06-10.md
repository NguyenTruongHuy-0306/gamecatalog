## Session 3 — Forgot Password: Email Delivery Fix + Resend UX

### `21b6475` — Fix forgot-password email delivery and transient 500 errors

End-to-end verification of the forgot-password flow uncovered two bugs:

**Empty env var bypass (`email.ts`)**
- `getFrom()` and `getAppUrl()` used `??` (nullish coalescing), which does not treat empty string as falsy
- `.env.local` was pulled from Vercel CLI with empty values for `RESEND_FROM_EMAIL` and `NEXT_PUBLIC_APP_URL`
- Resend received `from: ""` and silently rejected the send; reset links were never delivered
- Fixed: switched to `||` so empty strings fall back to `"onboarding@resend.dev"` / `"http://localhost:3000"`

**Transient 500 on DB operations (`forgot-password/route.ts`)**
- Neon serverless occasionally resets connections mid-request, causing an unhandled exception
- Next.js caught the throw and returned a bare 500 with empty body; the page showed "Something went wrong"
- Fixed: wrapped all DB operations (user lookup, token delete/create) in a top-level try/catch that logs the error and falls through to `reply()` — maintains enumeration protection while preventing 500s

Also configured `RESEND_API_KEY` locally (was never set in Vercel environment variables).
